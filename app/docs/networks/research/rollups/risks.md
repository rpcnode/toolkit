# Risks, unknowns and decisions the user must make (rollups family)

## Decisions

| # | Decision | Options | Recommendation |
|---|---|---|---|
| D-1 | **Container-only clients**: nitro (xai), zksync-era EN, scroll l2geth, immutable-geth, morph geth+morphnode, xlayer-reth+op-node publish NO release asset. Is registry-layer extraction (HTTPS blobs, no Docker daemon, = shipped arb/robinhood behaviour) acceptable under "no Docker install path"? | **R** registry pack (generalise `ArbNitroDockerPack`; docker.io + ghcr.io) / **B** fleet build (`build:` Dockerfile, optimism precedent; mandatory for arm64 of amd64-only images) / **S** on-host compile | R for xai, zksync, abstract, lens, morph (images are multi-arch, small); B for scroll + immutable arm64 and for xlayer (pair is already built from source upstream); S never. ## Unknowns I could not resolve without running the clients

* Exact first-start duration of: Xai (genesis replay), Immutable (full sync), Scroll (post-snapshot catch-up of ~4 months), ZK EN snapshot recovery per chain.
* Whether `sqlx database setup` is idempotent when the database already exists in a non-default tablespace (upstream entrypoint runs it on every start with the same call, so expected yes).
* Starknet: Juno `/ready` HTTP path (docs only name the flag), and whether L1 verification can be left off for a pure RPC node (`--disable-l1-verification` exists).
* X Layer testnet chain name for reth (`xlayer-testnet`, INFERRED from the mainnet name).
