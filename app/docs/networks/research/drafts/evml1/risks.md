Needs one question to the ShibaOne team (or a successful test sync). Also needs an Ethereum L1 RPC option (Heimdall v1) and the `tagSuffix` resolver. No snapshot, no Puppynet tip found.
3. **moca (NEEDS-DECISION).** `mocad` binaries are public, but there is no published genesis/seed/state-sync config; the repo README says "not ready for production use". Approve a cosmos-style install (genesis from `tm-rpc.mocachain.org/genesis`, state sync, seeds supplied by Mocaverse) or skip.
4. **"data" = DATA Network (formerly Story Protocol).** Confirm this is the intended chain (chain id 1514; "DATA" is the rebrand — evidence: `mainnet.datarpc.io` == `mainnet.storyrpc.io`; Goldsky/QuickNode list "DATA Network"). If another "data" chain was meant, tell me. Label drafted as "DATA Network"; env ids `mainnet`/`aeneid`; the client network names stay `story`/`aeneid`.
5. **gravity: L1 only.** Draft = Gravity Mainnet (L1, chain 127001) + Longevity testnet. The legacy Alpha Mainnet (L2, chain 1625, Nitro) is a different product on `rpc.gravity.xyz`; not drafted (would be an arb-recipe network). Confirm.
6. **plasma / monad / megaeth / ault / sahara = DEFERRED** (reasons in `networks.md`). What would unblock each: plasma — a published consensus binary (today container-only); monad — acceptance of apt/raw-NVMe/`/home/monad` layout (breaks "everything under node_dir"); megaeth — a released full node (only a stateless validator exists); ault — public `aultd` artifacts; sahara — binary releases + a mainnet. Their port blocks stay reserved.
7. **Architecture gate for sizes.** Most disk sizes are INFERRED (listed in D below). Approve the numbers or give measured ones before shipping.

## B. Core (shared) changes the drafts depend on — small but non-zero
1. `tagSuffix` filter in `ClientVersionSource.GitHubRelease`, `YamlClientProgramCatalog.parseSource`, `HttpGitHubReleaseClient.pickLatest` (gravity testnet; shibarium). Without it gravity testnet cannot resolve `v1.10.1-testnet`.
2. `urlTemplate: "github-asset:<glob>"` (`ClientArtifactUrlResolver`) for Nethermind (commit hash inside the asset name).
3. `UnitFlagOverrides.KEY` rejects upper-case keys and the locked-token check is case-sensitive → Nethermind presets (`JsonRpc.MaxBatchSize` …) would be rejected; relax and lower-case before `isLocked`.
4. JWT/identity under `<node_dir>/.toolkit/` (drafts) vs the existing chains' `/etc/<chain>/…` + `/opt/<chain>/…` (violates the brief's "node_dir only" rule; not touched).
5. Zip bundle installer (nethermind whole app, flare single file) and raw-binary installer; `NodeLaunchSpec.extractArchiveGlob/normalizeDir` for `ken-linux-amd64/bin/ken`.
6. A `kaia` URL probe must check `Content-Length > 1` (packages.kaia.io returns 200 + 1 byte for unknown paths).

## C. Platform limits (hard facts)
- **x86_64 only:** flare (`go-flare` zip), sonic (`sonicd`), vana mainnet patched geth, fluent, gravity. The wizard must refuse aarch64 for these (no `nameAarch64`). aarch64 OK: gnosis/joc (Nethermind), kaia, tempo, berachain, data, vana's Prysm + moksha geth.
- **Local NVMe mandatory** (vendor statements): tempo, sonic (EBS "does not provide the required latency and IOPS"), monad; gnosis docs prefer NVMe; berachain wants ≥1000 IOPS network volumes at minimum.
- **Huge downloads:** kaia mainnet snapshot 2.29 TB compressed (2.79 TB extracted) — single-pass `curl | tar --zstd` is needed; sonic archive genesis 181 GB (+ ~3 TB DB, hours of `sonictool genesis` at ~50 GiB RAM); berachain archive 1.2 TB + 336 GB; gravity 112 GB; tempo moderato 472 GB.

## E. Operational risks per network
- **gnosis:** Lighthouse default build must include gnosis (documented: `--network gnosis`); Nethermind `Init.BaseDbPath` is relative (`nethermind_db/gnosis`) so the DB lands under `--data-dir` — the disk role must be the data dir, not `--db-dir`. Reth-Gnosis has no binary releases (build only) — do not promise it. Erigon works but is not drafted.
- **joc:** Clique chain with 5 s blocks, small validator set; Nethermind's embedded pivot/bootnodes can go stale between Nethermind releases (docs-owner: Nethermind). Public RPC endpoints are third-party/consortium-run.
- **flare:** the docs say the bootstrap node IP/ID rotate; Start must fetch them every time and fail clearly if the three bootstrap hosts are unreachable (single point of failure). Version gating per network has hard deadline dates (v1.14.0 notes) — "latest stable" can be older than the required version if the project releases only rc + stable (v1.14.2-rc.0 exists). No arm64. `/ext/health|info|metrics` are on the public HTTP port.
- **sonic:** priming takes hours and is not resumable mid-import (script wipes and restarts); `--nat=extip` needs the public IP (script/Kotlin must discover it or accept `--nat=none`); `GOMEMLIMIT` must follow RAM (50 GiB sample is for 64 GB hosts) or the import OOMs; hardening: never publish debug/trace; `ftm` namespace deprecated (omitted).
- **kaia:** metrics (`--prometheus`) binds all interfaces — firewall; archive/full snapshots no longer available (archive = sync from genesis for weeks); `kend` wrapper must NOT be used (daemonises, breaks systemd ownership). Hardfork notes: every release is a hard-fork release until its activation block.
- **vana:** mainnet needs the **patched** geth (a mis-wired stock geth stops at block 9 228 152); both Vana images/binaries are single-vendor; config files should be pinned to a vana-com/vana release tag, not `main`; whitelisting is required for validators only. Moksha uses an old upstream Prysm (v5.1.0) — verify it still syncs.
- **tempo:** upgrades are version-gated per network (network-upgrades page); the node is trustless but depends on its upstream RPC serving certified consensus data; docs forbid network-attached storage and recommend chrony (clock skew rejects blocks). Snapshot + consensus data must come from the same snapshot.
- **berachain:** EL and CL versions must be the documented pair (bepolia = beacond v1.4.2-rc.0). The index.csv only listed mainnet rows on 2026-10-13. Restores must not overwrite `config/priv_validator_key.json`. beacond `proxy_app` and CometBFT RPC stay on 127.0.0.1.
- **data:** story-geth and story version independently; compatibility only in release notes. No official snapshot. Story v1.8.0 binary is 126 MB; install on small `node_dir` disks accounted for.
- **fluent:** young chain; releases roughly every 1-3 weeks and each ships its own genesis json.gz — mainnet/testnet chain files are built into the binary (no separate genesis step), but a version skew would fork the node. x86_64 only.
- **gravity:** hardfork activation times are compiled into the binary (miss one → fail-stop); the seed list is two Gravity-run hosts (mainnet) / one (testnet) — single-vendor dependency; identity file generated once must survive reinstalls; `identity` must never be copied from snapshots; heaviest config (YAML template + identity + reth flags).
- **All:** public tip URLs are third-party and rate-limited; the panel's "behind tip" is only as good as the listed URLs (drafts list ≥2 only for gnosis, chiado, sonic, berachain mainnet, data, joc).

## F. Security exposure checklist (what must not be public)
Engine/authrpc ports (all drafts: 127.0.0.1), metrics (127.0.0.1 except kaia `--prometheusport`), CometBFT RPC + proxy_app (berachain/data: 127.0.0.1), Lighthouse/Prysm APIs (127.0.0.1), gravity inspection, debug/trace/txpool/admin/personal namespaces, sonic IPC (disabled) + JS tracers + `ftm`, Avalanche-family `/ext/admin|info|health|metrics`, Heimdall REST swagger (if shibarium approved), any `--http.corsdomain *` + `vhosts *` combined with unauthenticated write namespaces. A rate-limiting caching proxy is required for public production traffic (same caveat as `prod-rpc-tuning.md`).
