# risks.md — unknowns and decisions (nonevm family)

## Decisions the user must make
1. **peaq has no binary.** Upstream = Docker image only (releases have 0 assets). Options: (a) `build:` fleet compile of the pinned tag (drafted; ~1 h Rust, needs a >=16 GB build agent, pin bumped by hand, `peaq-v0.0.113` has no GitHub release object); (b) extract the binary from the Docker image (violates the no-Docker rule); (c) DEFER peaq. Recommendation (a). Also confirm whether to ship the **agung** testnet (needs two chain specs + a private relay chain, tag family `peaq-dev-v*`).
2. **peaq relay chain:** embedded (default, self-contained, +~100 GB, own warp sync) vs reuse of a panel `polkadot` node (`--relay-chain-rpc-urls`, needs the new generic `parentNode` picker; works with `--rpc-methods safe` only INFERRED). Recommendation: ship embedded first, add external after a test.
3. **Stacks → Bitcoin (mainnet).** Reuse the panel's Bitcoin node (recommended) vs bundle a second bitcoind (rejected: duplicate IBD/disk). stacks-node authenticates only with `username/password`; the toolkit's Bitcoin Core is cookie-only. Decide: add an optional dedicated `rpcauth` user to the Bitcoin start (recommended), or read `.cookie` at every Stacks start (fragile), or require the operator to type credentials of an external bitcoind (`burnchain_*` options already allow it). Pruned Bitcoin only works AFTER the snapshot restore; the Bitcoin node must also be reachable on P2P 8333 from stacks-node.
4. **Stacks mainnet snapshot = 275 GB `tar.zst`** (required in practice). Needs a zstd codec in the agent's stream extract (today gzip only) and `zstd` in host deps; restore is destructive. Accept that, or run Stacks without a snapshot (weeks of sync, non-pruned Bitcoin).
5. **Aleo testnet:** only source builds exist (`testnet-v*` tags, 0 assets, different snarkVM; a mainnet binary cannot follow the testnet). Build (`snarkos.Dockerfile`, drafted) or ship Aleo mainnet-only. Aleo has **no linux-aarch64 binary** at all (mainnet) — aarch64 hosts only via `build:`.
6. **Polkadot on aarch64:** Parity publishes no linux-arm64 binary; compiling polkadot-sdk takes hours. Ship x86_64-only (as solana does) or add a `build:` later.
7. **Aleo `--rest-rps` default 10/IP:** behind the toolkit proxy every request shares one IP, so the vendor default is unusable. YAML follows the repo convention (vendor default visible, prod preset raises); I recommend shipping `1000` as the YAML value for aleo instead. Same question for `rpc-max-connections` (substrate default 100).
8. **Hedera DEFERRED** (permissioned consensus nodes; mirror node needs paid requester-pays buckets + Postgres/Citus, relay needs a funded account). Confirm DEFERRED, or define an "RPC gateway" product (mirror + relay against public mirror) — not a node.
9. **Polkadot snapshot runner is new agent code** (file-manifest, 16-20 parallel resumable GETs, no rclone). Alternative: install `rclone` as a host dep and shell out like the official recipe (simpler, extra dependency). Discovery scrapes the HTML table at snapshots.polkadot.io (no JSON index found) — ask Parity/IBP for a stable index or accept scrape breakage.
10. **Per-env values in network-wide `clientConfig` literals** (chain, network id, contract addresses, parachain id, bootstrap): no existing "per-env literal" binding source. Pick `envSections`-style or an `env_literal` source, or keep per-env tables in `<Id>UnitBodies` (sui style) and show the mainnet value in the preview.

## Unknowns (INFERRED / unverified — verify before coding)
- Polkadot snapshot dest layout `<base>/chains/<id>/{paritydb|db}/full/*` and that a mismatched `--database` ignores the restored DB; confirm with one real restore (Parity page says `chains/[chain_path]`, docs.polkadot.com parachain example uses `…/db`).
- Substrate pruned mode flags vs snapshot: westend `-prune` snapshot is pruning 1000, we pass 256 (number may change; INFERRED fine). `blocks-pruning 256` against `polkadot-paritydb-state-blocks-pruned` assumed to match its 256/256.
- `neard init --download-genesis --download-config rpc` output on the current 2.13.4 (flags VERIFIED in source, config URL VERIFIED, init itself not run — no linux host here). `store.path` absolute-path behaviour INFERRED. S3 bucket is the doc'd official build location but un-listable/unversioned; S3 binary's min glibc unknown.
- NEAR boot-node refresh depends on a public RPC being reachable at Start (same list as tip URLs). `rpc.mainnet.near.org` could be rate-limited/retired.
- Stacks: 4.0.5 was published the same day as this research (2026-10-13) — consider a minimum release age. Hiro testnet runs 4.0.1 while mainnet is on 4.0.4: a newer follower on krypton should be fine (sample conf at the tag carries the epoch table) but untested. The mainnet follower "read-only"/txindex defaults not changed; `stacks-blockchain-api` not shipped. Hardware (4 c/16 GB) and extracted-size (≲700 GB) are INFERRED.
- `sync → active` for Stacks: tip lag default ≤3 may flap (blocks every few seconds, Hiro tip can lead); may need a per-network `activeLag`.
- Aleo: `--logfile` + unit stdout split (two files) is a design choice; ephemeral client account regenerates a JWT file in node-data on every start (small, harmless; a persistent key file is optional hardening — format of `snarkos account new` output not verified). Mainnet binary built with default features includes metrics (`default = snarkos-cli/metrics …` VERIFIED). Hardware: README 24 c/128 GiB/2 TB vs docs.aleo.org lower figures (site Cloudflare-gated, unverified).
- Fuel: `rpc_args` (gRPC, default 4001) is `Option<RpcArgs>` — assumed off without flags; check with `ss -ltnp`. Chain-config `configs:` names with a sub-directory (`chain/…`) may not be supported by the sync — fallback: flat names + Start copies into `chain/`. `nodeInfo`/GraphQL not available until genesis import finishes (height probe returns null meanwhile). Fuel db size/sync time from genesis (66.7 M blocks) not documented. Relayer `eth_getLogs` paging against a public L1 will be rate-limited; a panel Ethereum node is the real answer.
- peaq: build deps list (`protobuf-compiler`, clang, lld) taken from the upstream Dockerfile/CI image purpose, not test-built. `peaq-dev-v0.0.109` build flags INFERRED same as mainnet. `--ethapi` tracing not enabled. peaq docs recommend `--state-pruning archive` on RPC nodes; the toolkit default follows that.
- Public tips: Paseo has two working providers (stakeworld, dwellir), Westend three; `rpc.ibp.network` and `paseo.dotters.network` answered empty from here (maybe geo/WS-only) — re-test from the panel host. Fuel/Aleo/Hiro tips are single-vendor.
- Substrate `chain_getHeader` is the best (non-finalized) head; reorg flaps of 1 block are normal.

## Conventions I deviated from / extended (flag in review)
- `clients.yml` artifacts that are zips (`stacks`, `aleo`) rely on a zip-capable extract; the repo's `extractArchiveGlob` path is tar-based.
- `build:` is used for peaq and aleo-testnet although it is a Docker-based *build* (not install) path — same precedent as optimism, xrpl, solana (`agave-validator`).
- Fuel unit has `EnvironmentFile=` (secrets out of argv/unit) — a deliberate extension of the shared unit template, no new placeholder needed.
- Port plan: peaq uses +5/+6 for the embedded relay; fuel keeps +7 reserved (gRPC must stay off); polkadot `p2p` is `protocol: both` (litep2p webrtc-direct UDP on the same number).
